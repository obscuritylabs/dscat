- REPO-004 Required approval count MUST be zero for the single-contributor workflow. Code-owner approval and last-push approval MUST remain disabled to avoid requiring another contributor. - REPO-005 Pull requests MUST merge through rebase to preserve individual atomic Conventional Commits. Agents MUST NOT merge a multi-feature branch by squashing away its individual feature commits. Branches SHOULD be kept small, integrated promptly by the agent after verification, and deleted after merge. Agents MUST NOT leave routine PRs waiting for the human to review or merge.
- REPO-006 Required status checks MUST be deferred until actual CI workflows and stable check names exist. Agents MUST then propose a remote ruleset update for only the selected minimal CI check context and MUST obtain explicit human authorization before applying it. Full applicable local lint, type, test/coverage, security, and package checks MUST be run and recorded before merge; separate Actions jobs for each check MUST NOT be required merely for branch protection. Local evidence MUST be reviewed alongside any small CI check, and the initial ruleset MUST NOT be described as enforcing CI.
- REPO-007 Agents MUST NOT directly push, force-push, delete, or bypass main protections. The one-time bootstrap recorded in REPO-011 MUST be treated as consumed; all subsequent work MUST use pull requests. Agents MUST NOT relax the policy or change repository visibility to overcome a failure.
