# Repository policy

- REPO-001 [FACT; HUMAN_DERIVED; 2026-11-16] Agents MUST prepare a GitHub-importable JSON policy for main on disk, MUST NOT add that JSON to version control, and MUST align operating instructions with the selected protections. The human MUST perform the requested import; this preparation MUST NOT be represented as remote activation.
- REPO-002 [FACT; LLM_INFERENCE] The local file MUST be local/github/main.ruleset.json and MUST remain excluded through .git/info/exclude. Agents MUST NOT use git add -f for it, copy its payload into a tracked file, or attach it to a pull request. Future protection changes MUST update both the local JSON and these policy instructions.
- REPO-003 [FACT; LLM_INFERENCE] The active branch ruleset MUST target refs/heads/main only, MUST block deletion and non-fast-forward updates, MUST require linear history and pull requests, and MUST require resolved review conversations. The bypass actor list MUST be empty.
- REPO-004 [FACT; LLM_INFERENCE] Required approval count MUST be zero for the single-contributor workflow. Code-owner approval and last-push approval MUST remain disabled to avoid requiring another contributor. New pushes MUST dismiss any stale approvals. Zero required GitHub reviews MUST NOT waive the human planning gates or release authorization.
- REPO-005 [FACT; LLM_INFERENCE] Pull requests MUST merge through rebase to preserve individual atomic Conventional Commits. Agents MUST NOT merge a multi-feature branch by squashing away its individual feature commits. Branches SHOULD be kept small and deleted after merge.
- REPO-006 [FACT; LLM_INFERENCE] Required status checks MUST be deferred until actual CI workflows and stable check names exist. Agents MUST then update the local ruleset and request re-import with required lint, type, test/coverage, and security check contexts. Until then all applicable checks MUST be run and recorded before merge; the initial ruleset MUST NOT be described as enforcing CI.
- REPO-007 [FACT; LLM_INFERENCE] Agents MUST NOT directly push, force-push, delete, or bypass main protections. If main does not yet exist, a one-time bootstrap from the existing initial planning commit MAY establish it before protection activation; subsequent work MUST use pull requests. Agents MUST NOT relax the policy or change repository visibility to overcome a failure.
- REPO-008 [FACT; LLM_INFERENCE] To install, the human SHOULD open repository Settings → Rules → Rulesets → New ruleset → Import a ruleset, select the local JSON, review the main target and active enforcement, and save. The human MUST ensure main exists before activation and the repository plan supports enforcement on private repositories. No repository update MUST be inferred from a local JSON validation.
- REPO-009 [FACT; TOOL_VERIFIED; 2026-11-16] The policy MUST be interpreted against GitHub's published [REST schema](https://github.com/github/rest-api-description/blob/main/descriptions/api.github.com/api.github.com.json): deletion, non_fast_forward, required_linear_history, and pull_request rule types and their configured parameters were inspected. Repository API inspection reported private visibility, rebase merge support, and no existing repository rulesets; the agent has push access but MUST NOT claim admin access or activation rights.

- REPO-010 [FACT; TOOL_VERIFIED; 2026-11-16] Readers MUST treat validation as local preparation evidence only: JSON parsing, main-only targeting, required rule/parameter fields against the published GitHub schema, and local Git exclusion checks passed. Remote rule activation MUST remain PENDING.
- REPO-011 [FACT; TOOL_VERIFIED; 2026-11-16] Agents MUST regard the one-time bootstrap as consumed: initial planning commit 062f492 was pushed to refs/heads/main before protection activation, establishing the target branch and verifying actual push access. Subsequent main changes MUST use pull requests.
