## Candidate assembly and publication

After I11 passes, integration MUST verify the final clean change on origin/main through protected PRs and record the exact main commit. R MUST build wheel/sdist once locally from that source using eligible pinned tools and frozen build constraints; `uv build --no-sources` MUST be supplemented with recorded age-constrained build-environment resolution, not assume isolated backend dependencies inherit project lock. R MUST inspect sdist rebuilding in a clean environment and wheel installation. Original verified artifacts MUST be retained; publication MUST upload those bytes without rebuilding.

The candidate MUST contain `dscat-0.1.0-py3-none-any.whl` (or actual compatible wheel tag), `dscat-0.1.0.tar.gz`, `SHA256SUMS`, CycloneDX1.6 `sbom.cdx.json`, separate build/dev inventory, VEX if applicable, source/artifact-binding manifest, neutral release notes, compatibility/support notices, concise verification report and the executed manual walkthrough. Filenames MUST reflect actual build output. Proprietary LICENSE/package/help and all required third-party notices MUST be verified in source/wheel/sdist. Download/installation instructions MUST match authorized repository visibility, include authentication when needed and omit credentials. Required authenticated released-asset verification MUST remain in force. Public visibility MUST NOT relicense the proprietary software or authorize public PyPI publication; no visibility change is included in this task.

R MUST record exact main/hash/check identities, versions/project scope and explicit exercise of DEC-045 standing delegation before tagging/publishing. Failed/skipped/stale security, licensing, schema, privacy, platform/desktop or installation checks MUST block that disposition. No further human release approval MUST be requested. R MUST verify remote-main/tag/artifact identities and published release asset list after upload.

## Downloaded-artifact verification and failures

A distinct fresh post-release V MUST use `gh release download v0.1.0 --repo OWNER/REPOSITORY --dir <empty-disposable-directory>` with authorized authentication, check all published SHA-256 values/source bindings, install downloaded wheel with `uv tool install --python 3.15.2 <downloaded-wheel>`, verify version/help/notices and execute applicable accepted scenarios plus minimum/detail/reload/both-export offline smoke outside the checkout. Actual filenames, environment and fixture hashes MUST replace placeholders in evidence. Downloaded sdist MUST contain approved planning/source/docs/notices and build/install successfully under frozen eligible constraints. Successful pre-upload testing MUST NOT stand for this stage. The release task MUST remain incomplete until its downloaded verification passes; verified source tasks MAY complete separately under governance.

Candidate failure MUST stop publication; normal implementation/fresh verification/PR correction, changed-artifact rebuild and full release-gate recheck MUST precede another readiness disposition. Hash-identical downloads MAY be retried after confirming expected identity. Post-publication failure MUST keep the release task incomplete and promptly notify the human of affected version/assets and safe-use assessment. Assets MUST NOT be silently replaced, versions reused, releases/tags deleted or stored data rolled back. Corrected content MUST receive a new verified versioned release under standing delegation; destructive withdrawal requires its separate explicit authorization. Evidence MUST distinguish the failed release from the correction.
