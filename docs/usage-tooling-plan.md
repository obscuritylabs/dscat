# Shared usage tooling implementation plan

## Authority and readiness

This task-scoped plan implements [the approved scope and architecture](usage-tooling.md), supporting CAP-05/NFR-006/NFR-007 and CAP-04/NFR-008. [Planning gates](planning-gates.md#shared-usage-tooling) owns disposition. Agent planning readiness, 2026-11-17: the ordered design below is ready for implementation after exact-candidate documentation QA/reconciliation. This is agent authorization, not human approval or executed acceptance. Product/catalog implementation, actual-history refresh, actual contributions/tracker publication and published protocol changes remain excluded. No additional human plan or release approval is required.

The maintenance package MUST remain separate from the future catalog package: project `dscat-usage`, import package `dscat_usage`, version `0.1.0`, Python `>=3.14`, stdlib runtime plus Git. Source MUST live in `tools/usage/src/dscat_usage`; packaging MUST live in `tools/usage/pyproject.toml`. This does not change the catalog's version, Typer/Pydantic boundary or approved product plan. Release tags MUST use `usage-v0.1.0` and subsequent compatible tooling versions, avoiding catalog release claims. No public Python API is promised.

## Frozen command contract

Both `python -m dscat_usage` and installed `dscat-usage` MUST expose the same commands. All commands except `--help`/`--version` MUST take explicit `--state PATH`; commands consuming configuration MUST take `--config PATH`. No default history discovery or network target is permitted. Human diagnostics MUST use bounded generic reasons; `--json` MUST emit a strict schema-v1 status object with `schema`, `status`, `counts`, `candidate_digest` and `remote_commit` (unavailable values null). It MUST NOT emit source identities or paths. Help MUST show the proprietary notice.

| Command/options in addition to state/config | Behavior |
| --- | --- |
| `setup --secret-file PATH` | Create private contributor/config/templates without replacing existing files; validate an externally provisioned 32-byte secret. Config MUST be explicit thereafter. |
| `map --entry PATH` | Validate a private schema-v1 mapping entry and locked atomic upsert; conflicting primary attribution MUST fail. Entry dimensions/precedence follow the specification. |
| `migrate --snapshot PATH --phase-map PATH --registry PATH [--identity-map PATH]` | Explicitly validate supported legacy snapshot/map inputs and copy into separate locked private state; optional private identity associations permit only uniquely verified native-identity promotion. Preserve legacy inputs/pointers; no refresh or Git transport. Unsupported/unsafe inputs fail `3`, attribution/identity conflicts fail `4`, lock contention fails `7`; unmatched identities remain historical/nonadditive with unavailable coverage. |
| `refresh` | Read only configured histories, freeze private source-prefix/SQLite observations and produce the next validated contribution. No Git transport. |
| `contribute --remote TARGET --branch NAME --generator-invocation ID` | Fetch, merge this computer's frozen contribution, render and freeze complete candidate; always stop for review. No push. |
| `check [--candidate DIGEST]` | Read-only revalidation of frozen inputs, ledger, complete outgoing tree and review bindings, if supplied. MUST NOT refresh, fetch or repair state. |
| `review --attestation PATH --execution-evidence PATH` | Validate externally supplied procedural fresh-review evidence and freeze its digest with attestation; MUST NOT author PASS evidence. |
| `update --remote TARGET --branch NAME --generator-invocation ID` | Without a candidate, prepare as contribute; with a frozen reviewed candidate, revalidate and ordinary-push without refresh. Stale parent MUST preserve old candidate, fetch/remerge/regenerate and require new review. |
| `readback --remote TARGET --branch NAME --expected-commit HEX --reader-invocation ID` | Separate fresh-execution clone validation of exact commit/ancestry, ledger, projections and generic metadata; record remote verification separately. |

Config MUST contain schema version, explicit source root/project selector, private map/rates/vocabulary paths, secret-file path and resource limits; these paths MUST remain private. Remote target MUST be supplied explicitly at preparation/resume and match frozen bindings. State MUST NOT be nested in a transport checkout. A local bare remote MUST work without a service. Actual publication remains outside this task pending the separate protocol transition.

Exit codes MUST be stable: `0` successful operation (including confirmed submission, separately from readback); `2` invalid arguments/schema/config; `3` missing/inaccessible/unsupported source or unsafe/corrupt state; `4` identity/domain/generation/measurement/mapping conflict; `5` independent review required, absent or stale; `6` transport failure or unresolved remote identity; `7` lock contention/recovery required. Review-required preparation MUST return `5` even when candidate creation succeeded. Error paths MUST preserve previous accepted pointers. JSON output MUST distinguish `prepared`, `review_required`, `submitted`, `remote_verified`, `unavailable`, `conflict` and `failed`; no submitted status implies fresh independent readback.

## Interfaces and schema ownership

U1 MUST freeze strict schema-v1 constructors/validators and typed dataclasses in `schema.py`; later increments MUST reuse them. Canonical JSON MUST use sorted keys, compact separators, UTF-8 and reject duplicate keys/nonfinite numbers. Every boundary MUST reject unknown keys, bool-as-int, unbounded strings/numbers, unsupported versions and invalid token subsets. HMAC tuples and domain marker MUST follow the architecture exactly. Defaults MUST limit each source file to 64 MiB, captured total to 512 MiB, records to 1,000,000 and generic diagnostic entries to 100; larger inputs MUST fail unavailable without replacing accepted state. Configurable limits MUST remain positive and bounded by these hard maxima.

| Interface/artifact | Owner and contract |
| --- | --- |
| `private.py`: `StateStore`, `atomic_write`, `locked`; private `manifest.json`, `map.json`, snapshots and pointers | U1; mode 0700 directories/0600 files where supported, exclusive owner lock, fsync/atomic replacement, symlink/path rejection, no automatic stale-lock deletion. Recovery MUST verify inactive owner. |
| `importer.py`: `capture`; `identity.py`: `receipt`; `mapping.py`: `resolve`; `migration.py`: `migrate` | U1; read-only supported native JSONL and SQLite history adapters, stable prefix capture/read-only transactions; private normalized records and digests. Unknown schema/identity MUST fail affected contribution. No hash-of-content identity fallback. Migration MUST implement the specification compatibility contract with validated legacy layouts, private historical archive and explicitly verified identity associations. |
| `schema.py`: `Contribution`, `Observation`, `Ledger`, `Candidate`, `ReviewEvidence`, `Attestation`, `Status` | U1; private raw associations MUST be structurally separate from transport observations. Strict validators for all later boundaries MUST exist before use. |
| `ledger.py`: `merge`; transport `usage-ledger.json` | U2; full latest observations keyed by contributor/generation/predecessor, exact receipt dedup, compatible enrichment only, conflicts quarantined privately and blocking. Explicit correction/removal MUST be represented and reviewed; unavailable input MUST NOT create replacement. |
| `metrics.py`: `aggregate`, `price`; `render.py`: `render` | U2; single canonical corpus, independent dimension precedence, global interval unions, Decimal dated/list counterfactual costs, strict public allowlist. Owned projection files MUST be `Usage.md`, `Usage-by-RTM.md`, `Usage-by-Task.md`, `Usage-Models.md`, `Usage-Methodology.md`, `Usage-Evidence.md`; other files MUST remain byte-identical. |
| `candidate.py`: `prepare`, `validate`; `review.py`: `validate_review`; `transport.py`: `submit`, `readback` | U3; private immutable candidate directory, tree/input/parent/generation/domain/schema/invocation/metadata bindings, ordinary push and remote identity confirmation, independent clone validation. |
| `cli.py`: `main`, package `__main__.py`; templates, user instructions and wheel/sdist | U4; command contract, clean install/offline walkthrough and release identity evidence. |

Transport observations MUST carry only the specification's allowed identity/framing/facts; generic metadata MUST use fixed neutral commit subject and explicit generic author identity. Private config MUST load exact reviewed model/provider/effort/tier vocabulary, public RTM inventory and opaque registered labels; missing vocabularies MUST produce unknown/unallocated, never free-form transport. Pricing templates MUST be empty by default; unknown prices remain unpriced. U1 MUST freeze sanitized synthetic compatibility fixtures for the existing schema-v1 snapshot/registry and phase-map layouts, including their private identity-association schema; no fixture MAY copy actual state. Migration input digests and private provenance MUST remain private. Canonical serialized schema fixtures MUST be frozen by U1 and expanded compatibly by U2/U3, with all changes reverified.

Review evidence MUST contain schema, opaque task ID, generator/reviewer invocation IDs, complete-candidate scope, PASS/FAIL disposition, candidate/tree/input/metadata/parent digests and evidence timestamp. Attestation MUST repeat exact bindings and reference execution-evidence digest. Both MUST be private and strictly validated; same invocation, wrong scope, absent/mismatched binding, changed candidate or evidence predating candidate creation MUST fail. A coordinator MUST provide real fresh-dispatch/return evidence and retain its provenance privately. This validator checks supported procedural bindings; it cannot authenticate reviewer honesty or independence against a process controlling private state. Synthetic evidence MUST be marked synthetic and accepted only for disposable local-remote test configurations. Production paths MUST consume real supplied evidence without placeholder hooks that reject every valid review.

## Local acceptance and tooling release

U4 MUST freeze eligible pinned build/lint/type/test tools with 14-day exclusion and hashes in a tooling-only uv lock without adding runtime dependencies. Applicable Ruff ALL, formatter and ty error-level checks MUST pass with narrow documented conflict exclusions. Verification MUST run `uv run --project tools/usage --frozen ruff check tools/usage`, `uv run --project tools/usage --frozen ruff format --check tools/usage`, `uv run --project tools/usage --frozen ty check tools/usage/src`, unit/branch coverage and the synthetic walkthrough. Exact supported flags/tool versions MUST be checked during implementation and any necessary compatible correction recorded before claiming success.

The walkthrough MUST create two separate temporary source/state roots and one local bare Git remote, seed an unrelated page, provision one synthetic secret outside Git, ingest native-format synthetic histories, migrate a synthetic legacy snapshot/maps into separate state and verify legacy byte preservation plus unknown/nonadditive handling, map opaque synthetic dispatches, prepare/review/push/readback both contributors, retry copied overlap, close an open turn, and prove stale review and conflict failures preserve accepted state. It MUST print expected aggregate/commit identities without private paths/IDs and clean up temporary data. The review fixture MUST explicitly describe its synthetic-only scope. Real review requires coordinator evidence from fresh execution; the walkthrough MUST NOT claim actual independent review occurred.

Fresh local acceptance MUST build `dscat_usage-0.1.0-py3-none-any.whl` and `dscat_usage-0.1.0.tar.gz` from the tooling project, inspect archives for secret/private data and source inclusion, install wheel and rebuild/install sdist in clean environments outside the checkout, and execute the same walkthrough without history/tracker/network access. Source distribution MUST include package tests, empty templates, instructions, license and approved maintenance plan/spec evidence, without packaging private state or catalog runtime claims. The implementation MUST preserve the root catalog pyproject and unrelated documents.

The tooling release MUST include original locally verified wheel/sdist, SHA256SUMS, source-commit/artifact manifest, a truthful tooling/runtime SBOM (stdlib/Git external prerequisite; no invented Python runtime dependencies), build/dev inventory, neutral notes and concise test/security/install evidence. Fresh advisory/exploitation/licensing applicability checks MUST cover actual build/dev dependencies and relevant prerequisites; unavailable/unknown status MUST remain explicit and block applicable readiness. Catalog schema/Excel/accessibility/product-release scenarios do not apply to this tooling-only artifact. [Delivery policy](governance.md#local-verification-and-distribution) and repository protection/PR policy apply; the catalog [delivery plan](delivery-plan.md) does not authorize or block unrelated catalog implementation here.

Integration MUST use protected PR/rebase flow, verify remote-main identities, then a fresh release agent MUST record DEC-045 standing delegation with exact main/artifact hashes and publish those same bytes. A separate fresh post-release agent MUST download `usage-v0.1.0` assets, verify hashes/version, install both downloaded artifacts in clean environments and run the synthetic/offline walkthrough plus released-source documentation checks. No actual wiki protocol migration/publication or private-history execution is authorized. Failure MUST keep the task incomplete and follow ordinary correction/new-version release policy; no silent asset replacement.
