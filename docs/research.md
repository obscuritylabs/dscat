# Standards and tooling research

- RES-001 [FACT; TOOL_VERIFIED; 2026-11-16] Planning MUST distinguish verified public specification guidance from deployment-specific obligations. Public sources alone MUST NOT be represented as proof that a particular regulation, internal policy, data marking, or sector exchange format applies to this tool.
- RES-002 [FACT; TOOL_VERIFIED; 2026-11-16] Readers MUST use the following source observations as research evidence, not as approved feature scope. Evidence was obtained by HTTPS retrieval and text/schema inspection on the stated date; mutable URLs MUST be pinned to a release or revision during implementation.

| ID | Source | Observation and planning consequence |
| --- | --- | --- |
| S01 | [DCAT-US 1.1](https://resources.data.gov/resources/dcat-us/) | The reference lists catalog fields including identifier, title, description, publisher, contactPoint, accessLevel, bureauCode, and programCode. A 1.1 exporter MUST validate required and conditional fields rather than fabricate missing values. |
| S02 | [DCAT-US 3.0](https://resources.data.gov/resources/dcat-us3/) | The guidance recommends 3.0 for new implementations and continued 1.1 operation during transition. It identifies JSON Schema 2020-12 rather than Draft-04 and changed field shapes. Agents MUST NOT treat 1.1 and 3.0 as interchangeable serialization targets. |
| S03 | [ODCS](https://bitol-io.github.io/open-data-contract-standard/latest/) and [repository](https://github.com/bitol-io/open-data-contract-standard) | The documentation describes schema, quality, ownership/team, roles, service levels, and other contract sections. Exact released version and supported sections MUST be selected before promising conformance. The mutable latest URL MUST NOT be a reproducibility anchor. |
| S06 | [Python downloads](https://www.python.org/downloads/) | The page lists Python 3.15.2 as the latest stable download at retrieval. Agents MUST recheck at implementation and verify dependencies support it; the locally installed 3.14.10 MUST NOT silently establish the target. |
| S07 | [uv settings schema](https://github.com/astral-sh/uv/blob/main/uv.schema.json) | exclude-newer accepts durations such as 14 days and compares individual distribution artifact upload times. Agents MUST validate duration support in the chosen uv version and apply the policy to development tooling as well as runtime dependencies. |
| S08 | [Ruff linter documentation](https://github.com/astral-sh/ruff/blob/main/docs/linter.md) | ALL enables all rules; some docstring rules conflict and are resolved automatically. Agents MUST document formatter conflicts and narrowly justify any further exclusions. |
| S09 | [ty configuration](https://github.com/astral-sh/ty/blob/main/docs/reference/configuration.md) | The rules table supports all as the default rule severity and error as a severity. Agents SHOULD use rules.all = "error" and MUST verify the pinned release supports the configuration. |

- RES-003 [ASSUMPTION; LLM_ASSUMPTION] The requirements SHOULD consider DCAT-US 3.0 as the primary export and 1.1 as a compatibility export; approval MUST settle whether both are in the first release.
- RES-004 [ASSUMPTION; LLM_ASSUMPTION] The workbook SHOULD capture dataset identity, description, owners/contacts, provenance, lifecycle, access restrictions, distributions/formats, and optional contract schema/quality metadata. Field-level mappings and requiredness MUST be approved; unknown values MUST NOT be invented to satisfy external schemas.
- RES-005 [ASSUMPTION; LLM_ASSUMPTION] ODCS SHOULD initially be an optional export only when sufficient contract metadata is supplied. Catalog metadata alone MUST NOT be assumed to supply schema, quality guarantees, or service commitments.
- RES-007 [ASSUMPTION; LLM_ASSUMPTION] The threat model SHOULD cover malicious XLSX ZIP/XML content, formulas and external links, output formula injection, accidental overwrite, dependency confusion, compromised artifacts, vulnerable dependencies, and disclosure through logs. Chosen mitigations and test limits MUST be specified in architecture and verification plans.
- RES-008 [FACT; TOOL_VERIFIED; 2026-11-16] Research coverage MUST be treated as incomplete for inaccessible sources: several vendor documentation and federal reference endpoints returned HTTP 403 anti-bot responses; some older reference URLs returned 404. Accessible upstream repository documentation supported the tooling findings. No unverified legal obligation MUST be promoted into requirements from these failures.
- RES-009 [FACT; LLM_INFERENCE] A 14-day artifact age cutoff MUST NOT replace vulnerability scanning, dependency provenance review, or a locked installation; it reduces exposure to newly published artifacts but does not establish safety.
