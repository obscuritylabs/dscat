- RES-002 [FACT; TOOL_VERIFIED; 2026-11-16] Readers MUST use the following source observations as research evidence, not as approved feature scope. Evidence was obtained by HTTPS retrieval and text/schema inspection on the stated date; mutable URLs MUST be pinned to a release or revision during implementation.

| S01 | [DCAT-US 1.1](https://resources.data.gov/resources/dcat-us/) | The reference lists catalog fields including identifier, title, description, publisher, contactPoint, accessLevel, bureauCode, and programCode. - RES-003 [FACT; HUMAN_DERIVED] The requirements MUST prioritize DCAT-US 3.0; optional 1.1 compatibility MUST NOT block the initial release, per DEC-006 D11.
- RES-004 [ASSUMPTION; LLM_ASSUMPTION] The workbook SHOULD capture dataset identity, description, owners/contacts, provenance, lifecycle, access restrictions, distributions/formats, and optional contract schema/quality metadata. Field-level mappings and requiredness MUST be approved; unknown values MUST NOT be invented to satisfy external schemas.
- RES-005 [FACT; HUMAN_DERIVED] ODCS MUST be an initial-release export per DEC-006 D11, with a minimal conforming mapping. Catalog metadata alone MUST NOT be assumed to supply schema, quality guarantees, or service commitments.
- RES-007 [ASSUMPTION; LLM_ASSUMPTION] The threat model SHOULD cover malicious XLSX ZIP/XML content, formulas and external links, output formula injection, accidental overwrite, dependency confusion, compromised artifacts, vulnerable dependencies, and disclosure through logs. Chosen mitigations and test limits MUST be specified in architecture and verification plans.
- RES-008 Historical retrieval notes reported inaccessible endpoints, but endpoint-specific response evidence is not retained here. This note MUST be treated as unverified historical coverage information, not a current endpoint/status check. No inaccessible or unverified source MUST establish a legal obligation or a clean research-coverage claim.
- RES-009 A 14-day artifact age cutoff MUST NOT replace vulnerability scanning, dependency provenance review, or a locked installation; it reduces exposure to newly published artifacts but does not establish safety.

- RES-010 [FACT; TOOL_VERIFIED; 2026-11-16] Agents MUST distinguish the following schema observations from the final chosen pins: the GitHub tagged-release API for [ODCS](https://github.com/bitol-io/open-data-contract-standard/releases/tag/v3.2.0) reported v3.2.0 (published 2026-09-08). Its tagged [schema](https://github.com/bitol-io/open-data-contract-standard/blob/v3.2.0/schema/odcs-json-schema-v3.2.0.json) requires top-level version, apiVersion, kind, and id and uses JSON Schema Draft 2019-09. Minimal technical schema validity MUST NOT be represented as meaningful contractual completeness.
