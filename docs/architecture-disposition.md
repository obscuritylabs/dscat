## Native platform decision

[Native platform design](architecture-platform.md) selects a sole outer process-launch owner with a nonblocking independent event loop, bounded closed control frames, owned child handles and pre-input READY/measurement acknowledgment. Full record/config/catalog parsing and result rendering stay inside the monitored coordinator/archive children. The outer process observes the exact children it launched; it never accepts arbitrary reported PIDs or executes workbook-controlled commands. Serial topology, fixed deadlines and explicit reap/error handling remain mandatory.

The macOS guard is a hard startup-relative map-size budget plus logical retained-state admission and asynchronous observed-RSS termination. It replaces an agent-selected absolute total-address-space metric; NFR-005 requires safe bounded termination under an approved threat model and does not itself specify 512 MiB total virtual memory. The old absolute ceiling is not silently claimed met. Preexisting mappings can be reused/committed and RSS polling can overshoot, so strict physical-memory containment is not promised. The allocation/lifetime graph names source-byte/model/copy/index/serialization peaks, reserves logical capacity before construction and removes full-catalog processing from the outer observer. These are dependent implementation changes; current source does not yet implement them.

## Supplied-commitment omission

The exact [first-release loss matrix](architecture-standards.md#optional-mappings-and-loss-matrix) deliberately emits neither quality nor service commitments in either initial target, including valid explicitly supplied assertions. This is a limited interoperability design, not deletion of collected information. FR-004 says commitments are included only when explicitly supplied: explicit supply is a necessary condition for inclusion, not a mandate to map every supplied assertion. FR-006/017 require capture, validation and preservation; FR-018 explicitly requires documented unmappable loss and canonical preservation. Those obligations remain intact. Required ownership/field-schema mapping scope is not removed.

Risk is moderate: consumers relying on exported assertions will not see supplied commitments. Mitigations are canonical round-trip preservation, per-record/per-field/per-target omission diagnostics without sensitive values, no fabricated guarantee, no live enforcement/agreement claim and user documentation naming the boundary. This disposition accepts that design scope without a human waiver or requirements change. Future supported commitment mappings require exact assertion semantics, pins/fixtures and affected architecture/plan gates. If implementation cannot preserve valid supplied assertions or report these losses, FR-017/018 acceptance fails and release is blocked. Planned fixtures MUST include supplied valid quality and service assertions omitted from both targets with corresponding loss reports, absent commitments producing no guarantees, malformed supplied assertions rejected, and canonical reload preserving supplied values.
