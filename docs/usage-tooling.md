# Shared usage tooling

## Scope and authority

This maintenance specification supports CAP-05/NFR-006/NFR-007 and CAP-04/NFR-008. The human approved the exact requirements decision package with SHA-256 `172c6139fde399335a83e62fe048d0d18b5ff2ef85cad2025cb3ab3deaf1ff43` on 2026-11-17. That package remains private; this sanitized specification records its operative scope. [Planning gates](planning-gates.md#shared-usage-tooling) owns disposition. Existing approved product requirements MUST remain unchanged.

Deliverables MUST comprise reusable tracked core tooling, synthetic tests, empty templates and setup/use instructions. Raw histories, private attribution/configuration/state, credentials, source paths and original identifiers MUST remain outside Git. Existing ignored tooling/maps MUST NOT be overwritten. Actual-history refresh, actual contributions, tracker publication and publication of the wiki protocol revision are excluded. Synthetic local Git end-to-end testing, tooling PR integration and tooling release/download verification are included.

## Architecture and boundaries

The tracked core SHOULD live under `tools/usage`, separate from ignored legacy tooling. It MUST be a typed standard-library maintenance tool, with explicit strict schema validation at every JSON boundary; it is separate from the planned Pydantic/Typer catalog runtime. Git is the existing transport dependency. No daemon, billing integration, hosted service or new runtime package is required. Planning MUST define packaging that makes this core runnable from downloaded installable tooling artifacts without implementing catalog commands.

The pipeline MUST separate read-only local importer, private mapping/receipt conversion, validated contribution ledger, deterministic aggregate renderer, frozen candidate, independent review with bound execution evidence and ordinary-push/readback. An implementation MAY adapt the existing importer only after sanitizing code, defaults, documentation and fixtures. Actual source access MUST require explicit local configuration. Synthetic tests MUST use explicit disposable sources/remotes/state.

### Private identity and merge

Setup MUST create a random contributor ID in private persistent state, independent of machine names, and require an externally provisioned 256-bit shared secret. It MUST NOT provision or transport that secret over Git. Private permission-restricted files MUST hold secret, source selector, maps, candidate inputs and receipts-to-source associations. A domain marker MUST be HMAC-SHA256 of a fixed versioned domain string using the secret; raw secret digests MUST NOT be exported. Different markers MUST fail rather than create a second corpus.

Receipts MUST use HMAC-SHA256 over canonical JSON tuples with explicit version/type domain separation: response identity includes native stable thread and response identity; turn identity includes native stable thread and turn identity. Neither tuple may include checkout path, hostname, tokens or mutable attribution. Thread/root/parent relationships needed for counts MAY use separately domain-separated keyed receipts, never original IDs. Missing/ambiguous stable source identity MUST quarantine records and block affected contribution; content-derived identities that change with observation MUST NOT be accepted as dedup proof.

The schema-v1 ledger MUST retain complete latest contributor observations, keyed by contributor ID and monotonic local generation with predecessor digest. An identical generation/digest is a no-op; differing content at the same generation, forks, rollback or lost contributor state MUST fail with recovery instructions. A new validated generation replaces that contributor's previous observation set, not a cumulative aggregate. Missing input MUST NOT generate an empty replacement. Preserved prior records and explicit removals MUST distinguish unavailable history from intentional correction; corrections MUST be reviewed.

Combined canonical records MUST be keyed by receipt across all latest contributions. Exact matching observations collapse. Unknown-to-known fact enrichment MAY merge only when non-null values agree; open-to-closed turn refinement MAY merge when known facts agree. Conflicting non-null token/model/timing or primary attribution values MUST quarantine the receipt and block the candidate, never silently prefer a contributor or count both. A later observation from one contributor MUST NOT overwrite contradictory evidence still supplied by another. Conflict diagnostics MUST expose counts and technical reasons, never raw identities. Private diagnostics MAY identify local records only in authorized private files.

### Allowlist and measurement semantics

Transport MUST reject unknown keys, arbitrary labels, nonfinite/negative numbers, booleans masquerading as integers, unsupported schema versions and inconsistent token subsets. Permitted facts comprise version/domain/generation framing, keyed relationship receipts, observation/event times needed for dated costs and interval unions, nonnegative token counters or null, bounded exact public model/provider/effort/tier enums or unknown, fixed phases, current public RTM IDs or shared/coordinator/unallocated, opaque registered task/feature labels, parent-known status, timing basis, and reviewed public rate provenance. Model/provider values MUST be configured from reviewed public vocabularies; free-form source settings MUST remain private/unknown. Contributor identifiers MUST be opaque. Arbitrary evidence strings, source hashes/paths, prompts, names and private attribution provenance MUST NOT enter transport.

Rendering MUST omit all receipts and contributor identifiers. Alternate requirement/task/feature/model views MUST reconcile to one response corpus; associated requirements MUST NOT duplicate primary allocation. Mapping precedence MUST remain response then turn then thread independently per dimension. Unsupported historical mappings MUST remain unallocated. Conflicting response-level categories MUST leave turn duration mixed/unallocated once.

Time MUST preserve recorded duration, explicitly counted derived fallback, summed closed intervals, global closed interval union, observation span, overlap/parallelism and open/missing counts as distinct facts. Timing includes source turns without responses; response-bearing turn counts use their own denominator. Model time and productive time remain unknown. Cross-computer unions MUST be recomputed from deduplicated intervals, never summed contributor wallclock. Category unions are nonadditive. Clock discrepancies MUST remain conflicts/limitations rather than fabricated precision.

Token metrics MUST retain known subtotals and missing counts; cached input is within input and reasoning within output. Decimal costs MUST subtract cached input before applying input rates, retain unpriced/invalid categories, separate currencies, apply event-date rates and independently compute measurement-date list-price counterfactuals. Unsupported cache writes, missing exact models/rates/tier constraints and unknown facts MUST remain unpriced. Actual bills MUST NOT be inferred. Measured-as-of and remotely confirmed publication time MUST remain separate; active tail and historical completeness remain unknown.

### Concurrency, review and failure

Private writes MUST use exclusive locks, temporary files, fsync where available and atomic replacement. A killed writer MUST leave previous pointers valid; lock recovery MUST require confirming the owner is inactive. Setup/read/write MUST reject symlinks, unsafe paths and corrupt manifests. Source file reads MUST use stable captured prefixes; SQLite MUST use read-only transactions. An observational snapshot MUST NOT claim cross-source transaction consistency. Limits on input bytes/records and diagnostic output MUST be explicit and tested. Parsers MUST NOT execute input content.

Candidate manifests MUST bind source/input digests, receipt domain/schema, contribution generations, remote parent, complete outgoing file-tree digests, generator invocation and generic author/message metadata. Review MUST cover all unchanged outgoing files as well as changed ones. Publication MUST recompute bindings immediately before commit/push; only owned ledger/projection paths MAY change. Preparation MUST stop with review-required status. Check MUST be read-only. Resume MUST use the frozen reviewed inputs, never refresh implicitly.

A reviewer-name CLI option or a bare PASS file MUST NOT establish independent review. The supported review operation MUST consume an exact-candidate attestation plus a separate fresh-execution evidence file supplied by the coordinator/reviewer workflow. Evidence MUST identify task, generator and reviewer invocation IDs, review scope, disposition and exact tree/input/metadata/parent bindings. The tool MUST reject identical invocation IDs, absent/mismatched bindings, stale evidence and an attestation lacking that evidence; it MUST NOT generate a passing review itself. The coordinator MUST establish from actual fresh-agent dispatch/return evidence that the reviewer invocation exists and is independent, retain that evidence privately, and provide the bound evidence file. The tool MUST validate its strict schema and freeze its digest before resume. This is a supported procedural trust boundary under the existing protocol, not cryptographic proof of reviewer identity: a process with full private-state access could forge files. Documentation MUST state that limitation and MUST NOT claim the validator authenticates semantic independence. Fresh independent review of the complete candidate remains mandatory on every computer; an alternate string alone never fulfills it. Synthetic tests MUST supply explicitly synthetic execution evidence only for disposable local remotes and MUST NOT reuse it for actual publication.

On stale parent, the tool MUST preserve the rejected candidate, fetch the accepted remote ledger, apply the pending contributor replacement, revalidate all overlap and regenerate from the new parent. A changed parent/tree/input/metadata MUST invalidate review. Ordinary push MUST never force or erase unrelated pages. An ambiguous push MUST query the remote commit and verify exact reviewed tree/ancestry before recording accepted status; uncertainty MUST remain pending, with retry/readback available. Only confirmed remote identity MAY update the local accepted pointer. Fresh independent clone/readback MUST validate ledger, projections and metadata after publication; local submit and remote verification MUST have separate statuses.

### Compatibility and migration

The command surface SHOULD retain `refresh`, `check`, `contribute` and `update` with explicit private source/state/configuration arguments. Planning MUST freeze exact options, schemas and exit codes before implementation. There is no public Python API commitment. Existing ignored snapshots/maps MUST remain usable by their old tool and MUST NOT be edited or automatically published by setup. An explicit private migration MUST support the existing schema-v1 snapshot bundle (manifest and hashed accounting outputs), phase-map entries, and schema-v1 reviewed attribution registry. It MUST validate supported layouts against synthetic compatibility fixtures, copy supported observations and explicit attribution into separate private state, and preserve every legacy input byte and old-tool pointer. Setup MUST NOT trigger migration. Repeated identical migration MUST be idempotent; failure or contention MUST leave both legacy and accepted new state unchanged.

Migration MUST preserve unknown/missing/open/unmapped distinctions, recorded attribution precedence and private evidence; inferred legacy labels MUST NOT become reviewed attribution. Unsupported versions, corrupt hashes, conflicting mapping dimensions, unsafe paths and ambiguous identity MUST fail with bounded generic diagnostics, never guess an allocation. Legacy truncated/derived identifiers MUST NOT establish receipt identity. Promotion to a receipt-backed contribution MUST require a unique privately supplied association verified against configured stable native source identities; unassociated observations MUST remain a private historical/nonadditive archive with explicit unknown corpus coverage. Missing histories MUST NOT erase preserved observations or produce an empty replacement. Private source identities, evidence, labels and associations MUST remain outside transport; only reviewed allowlisted facts MAY be promoted after identity validation. Migration MUST NOT transport secrets, auto-import private files into Git, refresh histories or publish anything.

Historical aggregate-only dashboards MUST NOT be summed with receipt-backed observations. Migration MUST either rebuild the complete intended corpus from available original histories under one receipt domain and review the replacement, or retain the legacy dashboard separately as historical/nonadditive and declare the new corpus boundary and incompleteness. Missing historical sources MUST remain unknown. Secret rotation/version changes MUST require explicit cross-domain dedup migration; until implemented they MUST fail closed.

The published wiki Usage-Refresh protocol still describes ignored single-computer tooling and a full identifier ban. This task MUST NOT update that published protocol or use the new ledger for actual contributions. Repository setup instructions MUST state that migration/publication remains excluded and needs a separately reviewed protocol transition before real use. Local synthetic end-to-end demonstrations do not establish tracker migration.

## Risk disposition and traceability

Agent architecture readiness, 2026-11-17: this design is ready for fresh planning, conditional on the exact-document QA/reconciliation required by [documentation QA](documentation-qa.md). This is agent readiness, not human architecture approval. No unresolved high-risk decision requires another human request. Stable receipt correlation is the explicit accepted requirements scope; it remains a moderate privacy risk. Compromised participating machines can expose the secret/raw histories, and a shared-secret ledger cannot authenticate measurement truth. Receipt HMACs provide correlation-resistant identity outside the trust group, not contributor honesty. Authenticated independent review and strict projection boundaries mitigate accidental disclosure; they do not make receipts anonymous. No actual histories, secrets or external publication are changed here, so the proposed maintenance implementation has bounded reversible effects.
