# Planning phase

The agent MUST first read [AGENTS.md](../../AGENTS.md) and the [planning index](../index.md), inspect Git status, and preserve unrelated changes.

This agent MUST follow the [workflow handoff](../workflow.md#bounded-handoff), verify its assigned revision and scope, and read [required sdlc and approval gates](../governance.md#required-sdlc-and-approval-gates), [traceability and change control](../governance.md#traceability-and-change-control), [local verification and distribution](../governance.md#local-verification-and-distribution), [definition of done](../governance.md#definition-of-done), [autonomous delivery ownership](../governance.md#autonomous-delivery-ownership), [engineering constraints](../engineering.md#project-and-engineering-constraints) and [catalog/licensing policy](../engineering.md#catalog-behavior-and-licensing), requirements and architecture dispositions, [planning gates](../planning-gates.md), and applicable [delivery proposals](../delivery-plan.md). It MUST load linked details relevant to its assignment rather than unrelated transcript history.

The agent MUST define small increments, ownership, dependencies, test inventory, exact local checks, manual walkthrough, security evidence and release conditions; apply standing release delegation and record readiness conditions.

The return MUST include an exact implementation-plan revision with agent readiness authorization, increment handoffs, verification arrangements, and standing release delegation/candidate evidence status. It MUST NOT request human plan approval. Documentation changes MUST receive [full documentation QA/QC](../documentation-qa.md). Unavailable evidence and later completion stages MUST remain explicitly pending.
