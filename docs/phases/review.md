# Review phase

This role applies only when selected by [proportional routing](../workflow.md#phase-routing). The agent MUST first read [AGENTS.md](../../AGENTS.md) and the [planning index](../index.md), inspect Git status, and preserve unrelated changes.

This agent MUST follow the [workflow handoff](../workflow.md#bounded-handoff), verify its assigned revision and scope, and read [authority and statement conventions](../governance.md#authority-and-statement-conventions), [required sdlc and approval gates](../governance.md#required-sdlc-and-approval-gates), [traceability and change control](../governance.md#traceability-and-change-control), [definition of done](../governance.md#definition-of-done), [engineering constraints](../engineering.md#project-and-engineering-constraints) and [catalog/licensing policy](../engineering.md#catalog-behavior-and-licensing), approved baselines, changed artifacts, traceability and verification evidence. It MUST load linked details relevant to its assignment rather than unrelated transcript history.

The agent MUST assess correctness, scope, security, maintainability and evidence as a distinct fresh agent that did not implement the reviewed increment; it MUST inspect primary artifacts and identify its review as agent independent review, never human approval.

The return MUST include findings with severity and scope, evidence and resolution status, and integration readiness or correction routing; an existing waiver MUST cite its explicit human decision and MUST NOT waive security or release evidence; the agent MUST NOT request a human review approval or waiver. Documentation changes MUST receive [focused documentation QA/QC](../documentation-qa.md). Unavailable applicable evidence MUST remain explicit; separate release work MUST NOT block this task unless included in its scope.
