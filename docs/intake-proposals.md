# Intake and catalog proposals

- INTAKE-001 [ASSUMPTION; LLM_ASSUMPTION] The human SHOULD review the following choices before requirements approval; these proposals MUST NOT authorize implementation.
- INTAKE-002 [ASSUMPTION; LLM_ASSUMPTION] A workbook SHOULD contain Instructions, Datasets, optional Fields, and optional Details/Quality sheets. Each dataset SHOULD occupy one main-sheet row. A stable ID SHOULD be preassigned by the maintainer and preserved by analysts; identifiers MUST NOT depend on filenames or row order.
- INTAKE-003 [ASSUMPTION; LLM_ASSUMPTION] Analyst-required fields SHOULD be title, short description, and a contact/owner, with a preassigned dataset ID. Capacity fields SHOULD accept explicit Unknown so participation is not blocked by unavailable measurements. Export-required shared metadata SHOULD be supplied through validated maintainer configuration when truthful, not fabricated defaults.
- INTAKE-004 [ASSUMPTION; LLM_ASSUMPTION] Optional details SHOULD include field names/types, provenance, retention, access restrictions, quality expectations, and service commitments. Empty quality or service fields MUST NOT be converted into guarantees. Workbook help SHOULD provide short examples and controlled choices where useful.
- INTAKE-005 [FACT; HUMAN_DERIVED] Capacity metadata MUST support current size, average and peak daily ingestion, retention, and measurement date, with explicit Unknown allowed, per DEC-012 D25. Unknown MUST remain distinct from zero. Additional size-basis and normalization choices MUST remain proposed under INTAKE-018.
- INTAKE-006 [FACT; HUMAN_DERIVED] Version 0.1.0 MUST export capacity metadata for human analysis and MUST NOT calculate forecasts. Explicit Unknown values MUST remain available so missing measurements are visible rather than interpreted as zero.
- INTAKE-007 [ASSUMPTION; LLM_ASSUMPTION] Canonical catalog JSON SHOULD preserve all validated intake metadata, including capacity and provenance; DCAT-US and per-dataset ODCS exports SHOULD be derived projections. A single format MUST be designated as the authoritative export so differing projections do not create competing sources of truth. The future viewer SHOULD read that canonical export.
- INTAKE-008 [ASSUMPTION; LLM_ASSUMPTION] Directory input SHOULD discover .xlsx files in one directory by default, ignoring Excel temporary lock files. Recursive discovery SHOULD require an explicit option. Discovery and record ordering MUST be stable. Inputs and output directories SHOULD be separate.
- INTAKE-009 [FACT; HUMAN_DERIVED] Identical records with the same dataset ID MUST be deduplicated. Different records sharing an ID MUST block export and report both source locations, per DEC-012 D24. Normalization and missing-ID behavior MUST remain proposed under INTAKE-017.
- INTAKE-010 [ASSUMPTION; LLM_ASSUMPTION] Each build SHOULD be a complete snapshot of explicitly selected inputs. Omitting a workbook SHOULD omit its records from the new snapshot without mutating an old snapshot; incremental merges and tombstones SHOULD remain outside initial scope. Existing output SHOULD require an explicit replacement option, with atomic publication and prior output preserved on failure.
- INTAKE-011 [ASSUMPTION; LLM_ASSUMPTION] Idempotence SHOULD mean byte-identical catalog exports for identical input content, configuration, and tool/schema versions. Serialization SHOULD use deterministic ordering and stable identifiers and MUST NOT inject current timestamps. Human-readable diagnostics MAY include input locations; reproducible catalog bytes MUST NOT depend on absolute paths.
- INTAKE-012 [ASSUMPTION; LLM_ASSUMPTION] Validation SHOULD run across every accessible workbook and accumulate independent file, sheet, row, field, and cross-record errors. It MUST NOT attempt to parse beyond unsafe resource limits or invent cascading errors when a parent structure is unreadable. No catalog export SHOULD be published on failure; a separate structured diagnostic report MAY be written.
- INTAKE-013 [ASSUMPTION; LLM_ASSUMPTION] Each workbook SHOULD embed a schema version independent of the package version. Supported older workbook fixtures SHOULD remain in regression tests. New optional columns SHOULD be preferred over breaking changes; migrations SHOULD preserve original intake files and require explicit output destinations.
- INTAKE-014 [ASSUMPTION; LLM_ASSUMPTION] Verification SHOULD cover Windows, macOS, and Linux, with desktop Excel used for a manual workbook round trip. CI availability, actual Python/dependency support, and human access to each platform MUST be confirmed before promising support.
- INTAKE-015 [ASSUMPTION; LLM_ASSUMPTION] ODCS 3.2.0 SHOULD be the candidate pin based on the observed latest release; the useful minimal export SHOULD contain stable identity, name, description, available ownership/schema metadata, and an explicitly defined contract version. Omitted metadata MUST remain absent rather than implying a contractual guarantee.

- INTAKE-016 [ASSUMPTION; LLM_ASSUMPTION] Workbook intake SHOULD validate into an internal Pydantic catalog model containing shared dataset metadata and capacity fields, then serialize to DCAT-US and ODCS. Optional canonical JSON persistence SHOULD be evaluated separately from that internal model; neither the internal shape nor authoritative JSON persistence MUST be treated as human-approved at this stage.
- INTAKE-017 [ASSUMPTION; LLM_ASSUMPTION] Duplicate comparison SHOULD operate on normalized business metadata, excluding file paths and row locations, while preserving all intake provenance. Missing IDs SHOULD fail rather than generating random identities. The normalization and identity allocation policy MUST be settled before implementation.
- INTAKE-018 [ASSUMPTION; LLM_ASSUMPTION] Capacity fields SHOULD distinguish logical/uncompressed from physical/compressed sizes, specify bytes versus decimal/binary units, and record the observation window for average/peak ingestion. Retention SHOULD allow a duration, indefinite, or Unknown. Numeric rates MUST NOT be interpreted as net storage growth without evidence.
