# Native platform resource design

This document owns the macOS-primary resource topology and allocation controls for NFR-001/005 under [DEC-048](decisions.md#dec-048). [Assurance](architecture-assurance.md#resource-enforcement-and-exact-package-matrix) owns the remaining lexical/archive limits; [the risk disposition](architecture-disposition.md#native-platform-decision) owns readiness and residual risk. This is a design candidate, not implemented behavior or observed product acceptance.

## Threat model and memory contract

Untrusted workbooks, configuration, canonical files and IPC MUST be treated as data processed by trusted pinned code. No formula, macro, expression, imported code or network reference from those inputs MAY execute. The design MUST bound input-driven parsing, retained representations and elapsed work, preserve committed outputs, and support retry. Arbitrary native-code compromise, a compromised interpreter/host and host-wide scheduler/kernel failure remain outside this tool's containment guarantees; process separation MUST NOT be described as an operating-system security sandbox.

The macOS adapter MUST combine a fixed finite map-growth limit, explicit allocation admission, independent resident observation and termination. It MUST NOT claim a strict 512 MiB resident, footprint or total-allocation ceiling. Preexisting allocator reservations can be committed/reused without increasing map size, and resident observation can overshoot or omit swapped/compressed charges. The previous agent-selected total 512 MiB address-space ceiling is replaced for macOS; NFR-005's bounded safe termination and hostile-input acceptance remain mandatory.

## Supervisor ownership and protocol

The outer CLI MUST be the sole process-launch owner. Its main event loop MUST supervise one coordinator and at most one serial archive worker, using the exact `Popen` handles it created. Processing MUST remain in those children; the outer loop MUST NOT parse workbooks, configuration, canonical catalogs or full record-bearing worker replies. No monitor thread inside a processing interpreter MAY supply the independent watchdog.

A separate private control pipe MUST carry closed typed messages, at most 4 KiB per frame and one outstanding worker launch request. Messages MUST contain only a fixed operation, monotonically increasing launch token, bounded source ordinal, ready/failure state and fixed exit/byte-count facts. They MUST NOT contain user values, paths, executable names or arbitrary PIDs. The outer launcher MUST choose the installed interpreter and fixed module itself and MUST obtain the child PID from `Popen`. The coordinator's worker-launch request MUST cause the outer owner to create the worker and connect its bounded data pipes to the coordinator; the outer loop MAY relay opaque bounded data chunks but MUST NOT decode their record payloads. Unknown, duplicate, out-of-order or oversized control messages MUST terminate the operation.

Each child MUST finish trusted imports and install its guard before emitting READY. Input forwarding MUST wait for the owner's ready acknowledgment and successful native measurement of that exact live child. A worker MUST never launch its own descendants. The outer loop MUST register ownership before input, retain unreaped handles until cleanup completes, and sample/kill only registered live children. It MUST poll exit status before/after sampling; after reap it MUST remove that identity and MUST NOT signal its numeric PID. Immediate PID reuse cannot occur while the owned dead child remains unreaped. Missing READY, reader failure, malformed control data and monitoring failure MUST terminate/reap the affected operation, without accepting an unmonitored interval of input processing.

The outer main loop MUST check deadlines and both registered resident sizes at a nominal 20 ms interval, without blocking on pipe writes/reads or joining a reader indefinitely. Bounded pipe queues MUST apply backpressure; no queued payload MAY exceed one 64 KiB chunk per direction. Its timeout checks MUST NOT depend on a child GIL or child-supplied clock. On worker failure it MUST kill and reap the worker and notify the coordinator using fixed facts; the coordinator MAY continue independent files within remaining budgets. On coordinator death, invocation timeout, SIGINT or watchdog failure it MUST stop/reap both children. Termination MUST allow at most one second for graceful shutdown then force-kill, with a two-second reap wait; inability to reap MUST be reported as operational failure, never success or successful cleanup. These are normal-scheduling bounds, not a guarantee during host suspension or kernel failure.

The coordinator MUST render final text/JSON diagnostics and assessment, including the existing versioned `CommandResult`, inside its monitored process. The outer CLI MUST forward only a bounded already-rendered result stream, at most 32 MiB, plus fixed control exit/receipt facts; no full catalog MUST return to the outer process. The outer loop MUST retain at most 64 KiB of that stream. Existing diagnostic-count, output privacy, JSON-only stdout and report-file behavior MUST be preserved. Partial streamed output followed by failure MUST have a nonzero exit and MUST NOT be described as a completed JSON document; the coordinator MUST stage/validate a complete structured result before transmission. Structured data/request/reply boundaries MUST remain Pydantic-validated inside monitored children, with maximum 32 MiB wire payloads and depth 64. The small control protocol MUST also use Pydantic closed models.

## Native adapters

On macOS each processing child MUST measure startup virtual bytes after imports, reject startup above 1 TiB, and install hard/soft `RLIMIT_AS` at that fixed measurement plus 512 MiB before READY. It MUST check native return/count/ABI values, addition overflow and exact limit readback. The measurement MUST never be rebased after accepting input. Each newly executed worker MUST independently establish its own guard; inherited coordinator accounting MUST NOT be reused. The 1 TiB startup sanity ceiling bounds the selected virtual metric only and MUST NOT be represented as physical-memory protection.

The outer owner MUST use `proc_pidinfo(PROC_PIDTASKINFO)` with the verified `proc_taskinfo` ABI on macOS to sample resident bytes of its owned children. A resident observation above 512 MiB MUST trigger termination. Unsupported ABI, denied sampling, short return, unavailable guard or limit/readback failure MUST fail closed with `RESOURCE_GUARD_UNAVAILABLE` before workload, or operational failure plus termination/reap during workload. The fixed 20 ms polling cadence is a scheduling target; resident overshoot has no claimed hard numeric ceiling.

Linux MAY retain its verified hard 512 MiB absolute `RLIMIT_AS` adapter. Windows MAY retain its Job Object process-memory limit and kill-on-close adapter. Adapter accounting differs and MUST be reported explicitly; successful verification on one system MUST NOT establish verification on another. Native macOS installation and complete workflow acceptance are required for first release. Windows/Linux remain portability targets and additional verification MAY proceed when available; neither is a mandatory first-release matrix entry. Missing required macOS safety evidence MUST still block acceptance/release.

## Allocation admission and lifetime graph

Finite source sizes alone are insufficient because shared strings, model construction, validation and serialization can amplify them. Each processing process MUST maintain a 128 MiB logical live-state admission ledger, separately from native/runtime memory and resident observations. This is an application-state budget, not an RSS or heap allocator limit. Every retained representation, index, container, string/value and simultaneously live conversion copy MUST be charged. Shared object identities MAY be charged once only while all retaining references are tracked; otherwise they MUST be charged conservatively at each retention. A mutation MUST reserve its prospective charge before construction/retention and release the charge only when its previous owners release it.

The conservative reservation MUST charge at least 1 KiB for each projected Python/model/container/scalar node, 128 bytes for each container/reference edge and four bytes per retained Unicode code point or numeric token digit, plus full bytes/bytearray capacity and scratch-copy capacity. The selected interpreter's actual object sizes MUST be checked against those conservative charges before enabling input; larger measured representations MUST increase the reservation or fail closed. This accounting is not a proof about every native allocator. Compound construction MUST reserve the entire projected subtree and conversion copies before calling Pydantic or materializing collections. Admission failure MUST return `INPUT_LIMIT` with fixed `memory` identifier and unexamined scope. All ceilings apply together, so nominal cell/record/snapshot maximums do not guarantee admission for every content shape.

| Stage and inspected source responsibility | Required live state, ceiling and release point |
| --- | --- |
| `intake.worker.read_source` | Count actual compressed input before retention, at most 32 MiB. Bytearray-to-bytes copies MUST be reserved together; release the mutable buffer after conversion. Source reading MUST occur only after READY. |
| `intake.archive.read_archive` / `read_member` | ZIP index at most 4,096 members, actual decompression chunks at most 64 KiB, XML part at most 16 MiB, workbook expansion at most 128 MiB. Compressed bytes, all retained expanded parts and current bytearray/copy MUST share the live-state ledger. A rejected admission MUST stop before retaining the new part. Member data MAY be spooled to private bounded temporary files and read one part at a time; aggregate expansion accounting MUST NOT reset when a part is released. |
| `intake.xml` / lexical preflight | Before Expat materializes an element/attributes, a bounded lexical scanner MUST reject start tags above 64 KiB and more than 128 attributes, with XML depth 64. It MUST preserve byte/declaration/entity rejection, UTF-8 correctness and incomplete-token handling. Expat's current token/native buffers remain bounded by the 16 MiB part source; they MUST be included in measured transient cases. No whole XML tree MAY be built. |
| `workbook.parse.StringEvents` / `WorksheetEvents` | Shared-string table, text fragments, cell dictionary and location/index objects MUST be charged before append/insert. Maximum individual text remains 32,767 code points and cells remain 200,000. Repeated references MUST reserve any copied normalized text; fragment joins MUST reserve old fragments plus joined value. Each expanded source part MUST be released after its semantic state no longer needs its bytes. |
| `parse_parts` / `normalize_batch` | Parsed row models, detail grouping, deduplication keys, field/service indexes and canonical records MUST share the ledger; conversion MUST reserve source plus target objects before construction. Release raw cell maps, intermediate row/group maps and their indexes after the corresponding normalization step. Neither source nor target ownership MAY disappear from accounting while still referenced. |
| `intake.worker` JSON admission and IPC | A nonmaterializing lexical pass over depth-limited JSON MUST count projected nodes, string code points and edges before `json.loads`/Pydantic. It MUST reject duplicate keys/nonfinite values without retaining an unbounded duplicate-key table. Reserve wire bytes, validation models and serialization scratch concurrently. Receiver queues remain 64 KiB; full record-bearing payloads remain at most 32 MiB. Parsing a full reply in the outer CLI MUST be removed. |
| `CandidateRecords` / `validate_catalog` | Before retaining each candidate, count deterministic serialized length and reserve catalog/index/assessment graph, plus current reply until released. Record count remains 100,000 and snapshot bytes remain 256 MiB, but logical live-state admission MAY reject earlier. Duplicate/conflict sorting and catalog validation MUST reserve their copies/indexes; no unbounded second catalog MAY be constructed. |
| Canonical load / save / publication | Individual JSON remains 32 MiB and aggregate snapshot 256 MiB. Serialization MUST stream per-record canonical chunks into private staging, with byte checks before writes and deterministic hashes updated in sorted artifact order. Writers MUST NOT retain a dictionary of all artifact bytes. Load/revalidation MUST retain at most one record's source bytes at a time and charge catalog/index objects. Previously loaded catalogs MUST be released before staging reload or included concurrently in admission; replacing outputs MUST NOT require retaining the old catalog. |
| Final result rendering | The monitored coordinator MUST reserve diagnostic/assessment models, render/validate bounded result bytes in private staging, then stream at most 32 MiB. Temporary/private files MUST NOT enter the committed generation or public projection. The outer observer retains fixed control state and one 64 KiB chunk only. |

The source inspection at baseline `253d9f1` found concrete dependent gaps: `read_archive` retains all expanded parts; `parse_parts` retains every worksheet cell map; row/group/canonical conversions overlap; JSON checks materialize before schema parsing; `CandidateRecords` serializes only after its source models exist; the outer CLI receives a full catalog. The in-progress storage design additionally retains all serialized artifacts, duplicates the catalog through JSON, and reloads a staged catalog while the original remains live. Those observations establish correction dependencies, not product findings covered by historical PASS results. No concurrent product edits are certified here.

Private spool files MUST be created with restrictive permissions, fixed generated names and exclusive ownership in the selected local workspace. The operation MUST account at most 256 MiB of aggregate staged canonical/result bytes plus one bounded input workbook's 128 MiB expanded spool; stale private spools MUST never be treated as committed generations. Cleanup MUST target only files owned by the current operation; interrupted orphan stages MUST remain safely unreferenced. Storage's complete flush/reload/hash validation and atomic CURRENT switch MUST remain; memory/spool exhaustion MUST leave CURRENT and previous generation bytes unchanged.

## Required feasibility and acceptance evidence

A synthetic native macOS ordinary-user probe on 2026-11-19 with CPython 3.15.2 installed hard/soft `RLIMIT_AS = startup virtual bytes + 64 MiB`, read back the exact value, refused a 96 MiB anonymous mapping and accepted/touched an 8 MiB mapping. Startup virtual bytes were 500476133376 and the enforced value 500543242240. An own-child `vmmap` summary showed a 385 GiB guard reservation; allocator environment switches did not make an absolute 512 MiB guard installable. This is small primitive feasibility evidence, not a product peak-memory claim. Native own-child `proc_pidinfo` returned the expected 96-byte task-info structure; sustained workload polling and identity/cleanup remain unverified. The external exact-probe record MUST accompany candidate review; product tests MUST NOT inherit a PASS from it.

Acceptance MUST establish installation/readback before input, actual safe refusal with injected small headroom, reused-reservation limitations without dangerous allocations, measurement denial/short returns, protocol/PID ownership and startup/exit races, a child holding its GIL, observer backpressure, timeout/kill/reap and invocation cancellation. Ledger tests MUST exercise every table stage at and above its allowed capacity, aliases/copies and reserve/release failures, giant XML tokens/attribute counts, tiny-node JSON amplification, repeated shared strings, full diagnostics and storage reload overlap. Maximum observed RSS/overshoot MUST be recorded honestly; finite observation MUST NOT be presented as proof of zero overshoot. Required hostile-input, existing-output preservation and clean retry remain acceptance/release gates.
